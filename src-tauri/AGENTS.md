# src-tauri/ (Rust shell)

Notes for agents working in this folder.

## Commands and windows

- Desktop commands are registered in `src/lib.rs` (`generate_handler!`, ~300 entries), wrapped by `route_commands`, which sends every `games_*` command to `harbor_games::invoke_handler()` (`games/src/lib.rs`, ~230 entries). Android has its own builder and list in `src/mobile.rs` (L80, ~65 entries: torrent engine, proxy, web server, settings, fetch bridge); it inherits nothing, so add a command there only if Android needs it. Games, music, mpv, casting and ffmpeg features are desktop-only. Gate platform-only entries with `#[cfg(...)]` inside the list.
- `run()` in `src/lib.rs` first checks `music::try_run_connector_worker` and the `games::try_run_*_worker`s: the same exe doubles as a worker subprocess, so a new worker mode needs a check there, before the Tauri builder.
- App commands need no capability entry from bundled pages, but plugin APIs do (`capabilities/*.json`), and capabilities match windows by label. A new window label needs adding to a capability's `windows` list; e.g. `harbor-video-pip` is only in `video-pip.json`.
- Capabilities are split by trust: `default.json` and `desktop-only.json` cover `main` only, `app-windows.json` gives the PiP, modal overlay and DJ deck windows only the plugin calls their code makes (fs scoped to the files they touch), and `external-windows.json` lists the third-party windows (`harbor-browser`, `harbor-cf-solver`, `source-verification-*`) with no permissions. A remote page reaches no IPC at all, app commands included, unless a capability has a `remote` block matching its URL, so these windows are driven from Rust: `cf_solver.rs` polls `window.__harborCfResult` with `eval_with_callback` every 500 ms (90 s limit, 8 Mi-char body cap), `browser.rs` closes on Escape by cancelling the sentinel navigation `harbor-close://now` in `on_navigation`, and `games/source_verification.rs` reads `window.__harborSourceResult` the same way. Never add a `__TAURI_INTERNALS__.invoke` to an external window's init script.
- The main window's fs and asset scopes are the standard dirs (`$APPDATA`, `$APPCACHE`, `$APPLOCALDATA`, `$TEMP`, `$DOWNLOAD`, `$AUDIO`, `$VIDEO`, `$PICTURE`, `$DOCUMENT`, each as `$X` and `$X/**`, since `X/**` does not match `X`) in `capabilities/default.json` and `tauri.conf.json` `assetProtocol.scope`. `fs_scope.rs` grants the rest at runtime: the folders in settings.json at setup and after each `settings_write` (`SETTINGS_FOLDER_KEYS`, plus `screensaverMedia` files), Steam artwork from the scan commands, `fs_scope_allow` for paths the frontend keeps elsewhere, and `allow_asset_directory` (asset scope only) for folders Rust keeps itself, such as the local music folder from `music-local.json` (`local::grant_saved_folder` at `music::initialize`, and on connect, scan and hydrate) so sidecar covers load after a restart. It refuses roots, home and its ancestors, dot folders, `AppData`/`Library` and the Windows folder. A new folder-valued setting goes into `SETTINGS_FOLDER_KEYS`. Opener's `reveal_item_in_dir` checks no scope at all (plugin 2.5.3), so reveal works anywhere.
- Secondary windows load the frontend with a `?harbor-*=1` query that `src/main.tsx` dispatches on.
- Tauri runs a non-`async` `#[tauri::command]` on the main thread, so a command that touches files, processes, an mpv instance or the network is `async` and does the work in `spawn_blocking` (`off_main` in `settings_store.rs`, `blocking` in `svp.rs`, `with_music` for the music database). Keep sync commands for lock reads and flag flips.
- `shutdown_services` (`lib.rs`) runs on the event-loop thread at window close and exit, so each subsystem waits through `block_on_bounded(label, budget, future)`, which spawns the future and gives up after its budget (2–5 s) with a `[harbor::shutdown]` line on stderr. Never call `tauri::async_runtime::block_on` there.
- `cast_server.rs` stops only a `stremio-server` whose executable sits in Harbor's own folder (`is_harbor_sidecar`), never one the user runs elsewhere.

## Cargo and platform gates

- `src-tauri/Cargo.toml` is both the `harbor` package and the workspace root: members `shared` (`harbor-shared`) and `games` (`harbor-games`). The `vendor/` crates are path dependencies under the root, so they are workspace members too (`cargo metadata` lists them); a vendored manifest's dev-dependencies would land in `Cargo.lock` and `flatpak/cargo-sources.json`, so vendored manifests carry none (`vendor/rust_cast` omits upstream's dev-dependencies). The single `Cargo.lock`, `[patch.crates-io]` and the profiles stay at this root, and `[workspace.package] version` is the version every member inherits (`scripts/bump-version.mjs` rewrites it). Plain `cargo test --manifest-path src-tauri/Cargo.toml` tests only `harbor`; add `-p harbor-games -p harbor-shared` (CI does). `harbor-games` is optional behind the default `games` feature.
- Code both the app and a member crate need goes in `harbor-shared`, and the app re-exports it under its old path (`use harbor_shared::child_pipe;` in `src/lib.rs`); a member never depends on `harbor`. A member that must call app code gets it as managed state (`FetchHook`).

- In `[target.'cfg(...)'.dependencies]`, `cfg(desktop)` silently matches nothing. Use `cfg(not(any(target_os = "android", target_os = "ios")))`.
- In `build.rs`, branch on `CARGO_CFG_TARGET_OS`, not `cfg!(...)` (that evaluates the host).
- The dev profile uses `opt-level = 2` for the crate and all deps, so the first build is slow. That is intentional.
- `[profile.release]` here is the shipping profile (fat LTO, one codegen unit, `strip = "debuginfo"` so crash-report backtraces keep function names, `panic = "unwind"` because `crash_report.rs` installs a panic hook). Local release speedups live in the git-excluded root `.cargo/config.toml`, whose `[profile.release]` keys override these (see the root `AGENTS.md`, "Release builds"); don't move them into the tracked `Cargo.toml`.
- Platform files use suffixes (`_windows`, `_win`, `_mac`, `_linux`); follow the suffix already used in the module you're editing.

## mpv

- One OS thread (`spawn_event_loop`, `src/mpv.rs`) waits on mpv and emits everything as `mpv://event` (`{event, ...}`); `time-pos` is throttled to 200 ms. Anything slow on that thread delays every playback event, so move it to `spawn_blocking`/`tokio::spawn`.
- Take a tokio child's pipes through `child_pipe.rs` (`take_stdout`/`take_stderr`/`take_stdin`, `output`, `wait_with_output`), never `child.stdout.take()` or `Command::output()`. On Windows tokio reads them with blocking `File` calls, and std aborts the whole process (`0xc0000409`, "operation failed to complete synchronously") when one is still pending; `child_pipe.rs` wraps them as overlapped named pipes. `std::process` pipes are safe.
- `mpv://event` payloads are the `MpvEvent` enum in `src/mpv_ipc.rs`. It, the mpv command argument structs (`MpvStartArgs`, `MpvGeometry`, `MpvSub`, `MonitorInfo`) and the results (`MpvProbe`, `AudioDevice`) derive `ts_rs::TS` and are exported to `src/lib/generated/mpv-ipc.ts`, which the player code imports. The `mpv_ipc::tests::export_bindings` test fails when that file is stale; regenerate it with `HARBOR_WRITE_BINDINGS=1 cargo test --manifest-path src-tauri/Cargo.toml --lib mpv_ipc` and commit both sides. To type another command, derive `ts_rs::TS` on its structs and list them in that module's `export_bindings` test, which hands the declarations and its file name to `ipc_bindings::check` (`#[ts(optional_fields = nullable)]` for `Option` fields the frontend may omit, `#[ts(type = "unknown")]` for `serde_json::Value`); each module writes its own `src/lib/generated/<name>-ipc.ts`. Commands keep `generate_handler!`; ts-rs generates types only.
- `app_features` (`src/app_features.rs`, also on Android) reports which optional crates the build has (`games`, `music`). The frontend reads it once before the first render (`src/lib/app-features.ts`) and hides those rooms, their nav entries, docks and settings, so a `--no-default-features` build never offers a command it lacks.
- On Windows `mpv.rs` finds its embedded child among the main HWND's children by `class == "mpv"` or an empty class with a title starting "Harbor", so no other child window (e.g. the `ytmusic.rs` embed) may have a title starting "Harbor".
- `stream_proxy.rs` never forwards `accept-encoding`: reqwest manages compression and rejects a manual header.
- Every mpv that Harbor starts, whether libmpv (`init.set_property("media-controls", "no")`) or the `mpv.exe` sidecar (`--media-controls=no` in `thumbs.rs`, `multiview.rs`, `dvr.rs` and clip export in `mpv.rs`), must turn mpv's own media controls off. An mpv that leaves them on adds a second card to Windows' media overlay next to Harbor's, titled with the file name.
- Windows' media overlay and the taskbar thumbbar live in `media_controls.rs` and `taskbar.rs`. `taskbar::register_app_identity` sets the AUMID `app.harbor` (the installer's shortcut ID) and writes a `DisplayName` under `HKCU\Software\Classes\AppUserModelId`, so a portable exe is not labelled "Unknown app". Thumbbar buttons can be hidden but never removed once added, so "no media" hides all seven.
- On Windows 11 the volume and media keys show only the small volume bar; the media card (title, artwork, timeline) appears only in Quick Settings (`Win+A`) and on the lock screen. Test the overlay there, not with the keys. Windows 10 still shows the card above the volume bar.

## Bundled inputs

- `externalBin` (`yt-dlp`, `ffmpeg`, `ffprobe` as `binaries/<name>-<triple>`), Windows `libmpv/libmpv-2.dll` and `resources/capstan/` come from `pnpm run setup`. `resources/pokemon-engine/` is NOT produced by setup (CI runs `node tools/pokemon-engine/build.mjs`); `scripts/pokemon-engine-stage.mjs` only creates it empty so the bundler accepts it.
- Linux `build.rs` panics if no libmpv is found (pkg-config `mpv`, then fixed lib dirs). CI installs `libmpv-dev`.
- Config overlays: `tauri.windows.conf.json` (auto on Windows), `tauri.linux-system.conf.json` (system ffmpeg/yt-dlp, no sidecars), `tauri.updater.conf.json` (CI Windows release only, so the NSIS `setup.exe` gets its updater `.sig`), `tauri.android.conf.json` (`build:tv`, no capstan).

## vendor/ and patches

- `vendor/leveldb-sys` builds via CMake from `src/build.rs` (not a root `build.rs`), with `CMAKE_POLICY_VERSION_MINIMUM=3.10` and `HAVE_CLANG_THREAD_SAFETY=OFF` pinned for CMake 4.x. On Windows it finds CMake via `vswhere`. Paths with spaces are quoted; keep it that way.
- `vendor/rust_cast` is built without its `thread_safe` feature, so a `CastDevice` is `!Send`. `cast_status` polls through one worker thread that owns its connection (30 s max age, 6 s read timeout via the vendored `set_read_timeout`); the LOAD session thread in `cast.rs` keeps blocking reads.
- `transcode::locate_ffmpeg`/`locate_ffprobe` cache the first path they find for the process, and `thumbs::is_hdr_source` caches each URL's successful probe (a timeout or non-zero ffprobe exit stays uncached).
- An ffmpeg/ffprobe/fpcalc run under `tokio::time::timeout` needs `kill_on_drop(true)`: tokio leaves a dropped `Child` running, so a timed-out probe keeps downloading. Cast control commands (`connect_control_device` in `cast.rs`) set a read timeout, since they hold `TRANSPORT_OPS` while waiting for the device.
- `web_server.rs` listens on `0.0.0.0`; its `/manga-img` proxy fetches through `http_fetch::public_http_client` and checks every redirect hop, so LAN clients cannot reach local addresses through it.
- `harbor_fetch` (`http_fetch.rs`) resolves each hop once in `validate_target` (`shared/src/net_guard.rs`; a failed or empty lookup is an error) and builds that hop's client with `resolve_to_addrs` on the checked addresses (`hop_client`, `pinned_client`), so a DNS answer that changes between check and connect is never used. `allowLocalNetwork` permits loopback and link-local targets but still pins them. `hop_client` reuses a cached client (`ClientCache`: 60 s TTL, 64 entries, LRU) only when scheme, host, port and the freshly validated, sorted address set are identical, so keep-alive and TLS sessions are reused while every hop is still validated and pinned. `pinned_client` itself never caches (`games/patch_download.rs` passes its own builder).
- `/api/remote` (`web_server.rs`) marks a socket `authed` when its upgrade query carries `k=<web_remote_token>` (64 hex, kept in `<app_data>/web-remote-token.txt`). Every phone URL and QR code appends it (`withRemoteKey` in `src/lib/remote/remote-auth.ts`), and the phone remembers it. `remote_ws_broadcast` reaches every socket, and unauthed ones get only `hello`/`pong`/`error`/`harborSetup` from it. `remote_ws_send(clientId, payload)` reaches one socket through `ClientRegistry` (removed on disconnect, false when gone) and also lets an unauthed socket receive its own `ack`; replies to one socket's frame (hello, pong, errors, pairing and Play-on acks via `sendToRemoteClient` in `play-on-route.ts`) use it, while snapshots and the TV hand-off offer stay broadcast. `host-mount.tsx` drops unauthed control commands (`remoteFrameAllowed`). Harbor-to-Harbor Play-on frames (a nonce `id` plus a `playMeta`/`queueMeta`/`setConfig`/`setTheme` action) are routed by `src/lib/remote/play-on-route.ts` and act only with the phone key or a paired token (`verifyPlayOnFrame` in `src/lib/lan-trust-host.ts`, which stores only the token's SHA-256). The host's hello advertises `trust`, pairs through `pair begin`/`pair code` with an 8-character code shown on its screen, adopts a sender-proposed token without echoing it (a host-issued one goes only to the pairing socket), and allows 3 `begin`s per 60 s and 15 failed codes per 10 min across all sockets, answering `busy` past either (`SlidingWindow` in `lan-pair-host.ts`).
- Open item: the torrent engine's LAN server (`torrent_engine.rs`, `0.0.0.0:11470`, `/{hash}/create`) has no authentication, since Stremio-protocol clients and the Android TV shell call it.
- `[patch.crates-io]` patches `librespot-core` and `librqbit`. Read the comments in `Cargo.toml` before bumping either.

## Tests

- No integration tests: `tests/` holds only fixtures (pulled in with `include_bytes!`). Tests are inline `#[cfg(test)]` or sibling `*_tests.rs` (`games/src/`, `src/music/engine_tests.rs`).
- Single test: `cargo test --manifest-path src-tauri/Cargo.toml <module::path substring>`, with `TAURI_CONFIG` set as in the root notes if setup wasn't run.
