# Architecture follow-ups

Findings from the October 2026 architecture review that `fix/architecture-review` did not fix. That branch covers the trust boundary, secrets, settings durability, the Rust/TS episode rule, dead `harbor.site` calls, Play-on pairing, the Cloudflare solver and browser windows, chrome buttons under the CSP, per-client remote replies, credentialed streaming requests, the Memory HUD's fetch wrapper, queued navigation updates, dead mpv listeners, bounded shutdown waits, blocking commands on the main thread, the stremio-server kill, provider calls outside `safeFetch`, `safeFetchLocal`'s local-network grant, the shared dev proxy list, the debrid library caches, the HDR stage's repeated sends, settings writes during render, the shared `safeFetch` blocklist, view definitions, the profile roster, settings migrations, `lib/` → `views/` imports, typed `harbor:*` events, and the mpv bridge split (configuration, session, events, geometry, parsing, subtitles and audio in their own modules).

Each item says what is wrong, where, why it matters, and a suggested fix. Read `AGENTS.md`, `src/AGENTS.md` and `src-tauri/AGENTS.md` first: they list the test traps (source-regex tests, mock `require` lists) that these files are covered by.

## Decided not to fix

- **Torrent engine LAN server** (`src-tauri/src/torrent_engine.rs`, `0.0.0.0:11470`, `/{hash}/create`) has no authentication. Stremio-protocol clients and the Android TV shell (gitignored `android-native/`, not in this repo) call it, so a key would break clients this repo cannot update. Revisit only together with a TV shell release that learns the web remote key.
- **Direct `fetch` calls that stay direct.** After the provider, tracker and AI calls moved to `safeFetch`, the remaining global `fetch(` calls read `blob:`/`data:`/same-origin URLs (avatars, icons, `/spooktober/`, `/manga-img`, `/anime-hero-art.json`, `convertFileSrc` files), talk to the local torrent engine or Stremio server, post `FormData` to Harbor's dead account API, run the stream-plugin sandbox's own `fetch`, send `keepalive` scrobbles that must outlive the page, run only off-Tauri (Modrinth in `games/mods.ts` and `minecraft-catalog.ts`, which use `invoke` in the app), or measure raw download speed (`speed-test-run.ts`). `harbor_fetch` cannot carry `FormData`, `keepalive` or a streamed body, so moving those would break them.

## Structure (refactors, own branch)

1. **`createMpvBridge` still owns `load` and the property setters (~570 lines).** Configuration (`mpv-config.ts`), the retained Windows session (`mpv-session.ts`), event rules (`mpv-events.ts`, a pure reducer), geometry (`mpv-geometry.ts`), parsing (`mpv-tracks.ts`), subtitles (`mpv-subtitles.ts`) and audio (`mpv-audio.ts`) are separate modules. What remains is `load`'s ordered steps, whose order two tests pin by source position, the effect runner, and one-line property setters; splitting those further would only add indirection. Revisit if `load` grows again. The PiP window is a separate webview playing its own `<video>`, so its `currentTime` is that window's position, not a copy of the mpv one.

## Platform migrations

Each of these has its mechanism and a first converted area in place; the rest moves over one area per branch.

1. **Generated IPC types.** `src-tauri/src/mpv_ipc.rs` exports the mpv command structs and the `mpv://event` enum to `src/lib/generated/mpv-ipc.ts` with ts-rs, and `mpv_ipc::tests::export_bindings` fails when that file is stale (see `src-tauri/AGENTS.md`). The other ~540 commands and their ~690 `invoke` calls still declare argument and result types by hand on each side. Move one module at a time (settings, streams, cast, music), deriving `ts_rs::TS` and adding the types to `bindings()`, or a per-module bindings file once one gets long. tauri-specta would also generate the `invoke` wrappers, but its Tauri 2 line is still a release candidate (2.0.0-rc.26 with an exact specta pin) and takes over the single `invoke_handler`; reconsider when it ships a stable 2.x.
2. **Durable user data.** `src/lib/durable-store.ts` mirrors the keys in `DURABLE_PREFIXES` into `user-data.json` (`user_data_read`/`user_data_write`), restoring them into a WebView profile that lost them. Only the watch-event log uses it so far; about 980 `localStorage.` call sites remain. Next candidates, in order: playback history (`playback-history.ts`, which `storage-recovery.ts` currently lists as prunable on a quota error), the watchlist (`watchlist.ts`), manual watched marks (`manual-watched.ts`), custom lists and collections. Large recomputable caches stay in localStorage or IndexedDB. Once most user data is in the file, backups (`lib/backup.ts`) can read it instead of scanning localStorage.
3. **Rust workspace.** `src-tauri/Cargo.toml` is a workspace with `harbor-shared` and `harbor-games` (behind the default `games` feature). `music` (~29k lines) is the next candidate but needs two seams first: it uses `crate::mpv` (`AudioDevice`, `mpv_argv_command`) and `crate::settings_store` secrets, and `mpv.rs` calls `music::pause_for_video` back. Move the mpv helpers into `harbor-shared`, and pass the pause call and the secret reads in as managed state, the way `FetchHook` passes `harbor_fetch` to games. The frontend still shows the Games room when the app is built with `--no-default-features`; it would need a capability flag from Rust to hide it.
4. **Typecheck speed.** CI runs `typecheck:fast` (TypeScript 7, about 15 s) next to the TypeScript 5.8 check (about 2 min). The locale modules are not the slow part: checking all 2,294 locale files alone takes under 5 s of the 113 s run, and each locale already loads lazily, so converting them to JSON would only break the Crowdin and `check-i18n` tooling that parses them. The TypeScript 5.8 check can go once the language server works with TypeScript 7 (7.0.2 ships no `tsserver.js`).
5. **React Compiler.** It compiles only the folders in `REACT_COMPILER_DIRS` (`vite.config.ts`), starting with `src/components/notification-center/`. Add folders one at a time, starting with leaf components; there are about 4,000 `useEffect` call sites, and hand-written `useMemo`/`useCallback` can go once a folder is compiled and verified. No lint rule enforces the Rules of React yet: `vp check` (oxlint) has no React Compiler rules, and `eslint-plugin-react-hooks` 7 would mean adding ESLint.
6. **Source-text test pins.** About 300 test files read a module's source with `readFileSync` and match it with regular expressions, so a rename breaks them while a real behavior change can pass. `tests/activity-watch-events.test.ts` checks the watch log by behavior. Next, the `mpv-config.ts` pins in `monitor-feature-contract.test.ts` and `playback-critical-path.test.ts` can be replaced by assertions on `defaultVodBufferProperties` and `mpvStartArgs`, which `tests/mpv-config.test.ts` already imports.
