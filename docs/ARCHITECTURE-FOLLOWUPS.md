# Architecture follow-ups

Findings from the October 2026 architecture review that `fix/architecture-review` did not fix. That branch covers the trust boundary, secrets, settings durability, the Rust/TS episode rule, dead `harbor.site` calls, Play-on pairing, the Cloudflare solver and browser windows, chrome buttons under the CSP, per-client remote replies, credentialed streaming requests, the Memory HUD's fetch wrapper, queued navigation updates, dead mpv listeners, bounded shutdown waits, blocking commands on the main thread, the stremio-server kill, provider calls outside `safeFetch`, `safeFetchLocal`'s local-network grant, the shared dev proxy list, the debrid library caches, the HDR stage's repeated sends, settings writes during render, the shared `safeFetch` blocklist, view definitions, the profile roster, settings migrations, `lib/` → `views/` imports, typed `harbor:*` events, the mpv geometry tracker and mpv's track and property parsing.

Each item says what is wrong, where, why it matters, and a suggested fix. Read `AGENTS.md`, `src/AGENTS.md` and `src-tauri/AGENTS.md` first: they list the test traps (source-regex tests, mock `require` lists) that these files are covered by.

## Decided not to fix

- **Torrent engine LAN server** (`src-tauri/src/torrent_engine.rs`, `0.0.0.0:11470`, `/{hash}/create`) has no authentication. Stremio-protocol clients and the Android TV shell (gitignored `android-native/`, not in this repo) call it, so a key would break clients this repo cannot update. Revisit only together with a TV shell release that learns the web remote key.
- **Direct `fetch` calls that stay direct.** After the provider, tracker and AI calls moved to `safeFetch`, the remaining global `fetch(` calls read `blob:`/`data:`/same-origin URLs (avatars, icons, `/spooktober/`, `/manga-img`, `/anime-hero-art.json`, `convertFileSrc` files), talk to the local torrent engine or Stremio server, post `FormData` to Harbor's dead account API, run the stream-plugin sandbox's own `fetch`, send `keepalive` scrobbles that must outlive the page, run only off-Tauri (Modrinth in `games/mods.ts` and `minecraft-catalog.ts`, which use `invoke` in the app), or measure raw download speed (`speed-test-run.ts`). `harbor_fetch` cannot carry `FormData`, `keepalive` or a streamed body, so moving those would break them.

## Structure (refactors, own branch)

1. **`createMpvBridge` in `src/lib/player/mpv.ts` is still one closure (~1,350 lines).** Embed geometry lives in `mpv-geometry.ts`, and track/chapter parsing, external-subtitle metadata and the one-to-one property mapping in `mpv-tracks.ts`. What remains (subtitle add/translation/selection, load, the stateful event branches) shares the closure's ~30 `let` variables. Many tests regex-match its text (`playback-critical-path`, `monitor-feature-contract`, `player-startup-readiness`, `subtitle-player-lifecycle`, `mpv-audio-device-reload`) and `tests/helpers/mpv-bridge-harness.ts` evaluates it with a mock `require`, so each extracted module needs its harness entry and the regexes moved with it. Fix: move that shared state into one explicit object first, then the subtitle code can leave the closure. The PiP window is a separate webview playing its own `<video>`, so its `currentTime` is that window's position, not a copy of the mpv one.
