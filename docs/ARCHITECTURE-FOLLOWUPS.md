# Architecture follow-ups

Findings from the October 2026 architecture review that `fix/architecture-review` did not fix. That branch covers the trust boundary, secrets, settings durability, the Rust/TS episode rule, dead `harbor.site` calls, Play-on pairing, the Cloudflare solver and browser windows, chrome buttons under the CSP, per-client remote replies, credentialed streaming requests, the Memory HUD's fetch wrapper, queued navigation updates, dead mpv listeners, bounded shutdown waits, blocking commands on the main thread, the stremio-server kill, provider calls outside `safeFetch`, `safeFetchLocal`'s local-network grant and the shared dev proxy list. Line numbers are from commit `273ea4bb`; check them against the current tree before editing.

Each item says what is wrong, where, why it matters, and a suggested fix. Read `AGENTS.md`, `src/AGENTS.md` and `src-tauri/AGENTS.md` first: they list the test traps (source-regex tests, mock `require` lists) that these files are covered by.

## Decided not to fix

- **Torrent engine LAN server** (`src-tauri/src/torrent_engine.rs`, `0.0.0.0:11470`, `/{hash}/create`) has no authentication. Stremio-protocol clients and the Android TV shell (gitignored `android-native/`, not in this repo) call it, so a key would break clients this repo cannot update. Revisit only together with a TV shell release that learns the web remote key.
- **Direct `fetch` calls that stay direct.** After the provider, tracker and AI calls moved to `safeFetch`, the remaining global `fetch(` calls read `blob:`/`data:`/same-origin URLs (avatars, icons, `/spooktober/`, `/manga-img`, `/anime-hero-art.json`, `convertFileSrc` files), talk to the local torrent engine or Stremio server, post `FormData` to Harbor's dead account API, run the stream-plugin sandbox's own `fetch`, send `keepalive` scrobbles that must outlive the page, run only off-Tauri (Modrinth in `games/mods.ts` and `minecraft-catalog.ts`, which use `invoke` in the app), or measure raw download speed (`speed-test-run.ts`). `harbor_fetch` cannot carry `FormData`, `keepalive` or a streamed body, so moving those would break them.

## Bugs

1. **Writes during render.** `src/lib/settings.tsx:169` calls `setTmdbLanguage` and `:422` calls `applyProviderKeys(settings)` during render (guarded and idempotent, and documented in `src/AGENTS.md` as deliberate so children in the same pass read the new value); `src/lib/settings/load.ts:335` calls `adoptLegacyPlaylists`, which writes localStorage, from inside `parseStoredSettings`. That adoption is load-bearing: Big Picture's playlist form (`views/big-picture/bp-live-setup.tsx`) saves through `update({ iptvPlaylists })`, and the next parse of the blob is what moves the entry into `harbor.iptv.playlists.v1`. Fix: first make Big Picture add and read playlists through `lib/iptv/playlists-store.ts` (`use-bp-live.ts` and the BP settings rows also read `settings.iptvPlaylists`, which the parse deletes), then move the adoption into a one-time startup migration; replace the render-time setters only together with a `useSyncExternalStore` store their readers subscribe to.

## Network layer

2. **Five `safeFetch` entry points with different rules.** `safeFetchBase64`, `safeFetch`, `safeFetchLocal`, `safeFetchStream` and `safeFetchBytes` each apply their own blocklist, deadline and fallback policy. Fix: one internal request function with explicit options (streaming, base64, local network, deadline) that the five call.

## Structure (refactors, own branch)

3. **`src/lib/view.tsx` (1,985 lines).** A navigation provider with about 90 context fields, plus domain types (`PlayEpisode`, `PlayerSrc`, `PlayerStreamRef`) that unrelated modules import. Adding a view means editing the `View` union, the derivation chain, `frameKey` and `setView`. Fix: move the domain types to their own module, and drive the four places from one table of view definitions.
4. **`src/lib/player/mpv.ts` (1,673 lines).** `createMpvBridge` (`:270`) is one closure to the end of the file. Playback position lives in four copies: the mpv snapshot, `lib/player/playback-clock.ts`, React state and the PiP window. Fix: split the bridge into event handling, commands and snapshot modules, and make `playback-clock` the single position store the others subscribe to.
5. **The profile list has about 25 readers.** `localStorage.getItem("harbor.profiles.v1")` is parsed in about 25 modules, each with its own fallback (`settings.tsx`, `profile-store.ts`, `auth.tsx`, `cw-profile.ts`, `i18n/store.ts`, …). Fix: one reader in `lib/profiles` with a typed result, and replace the copies.
6. **Settings migrations use flags in user data.** About 20 booleans such as `_mpvEmbedV3`, `_playbackSourcePreferenceV1` and `_animeRowsV1` in the settings object record which migrations ran (`src/lib/settings/load.ts`). Fix: a numeric schema version and an ordered list of migrations.
7. **Layering.** Five `lib/` modules import from `views/`: `addons-anime-filter.ts`, `remote/host-mount.tsx`, `remote/remote-open-bridge.tsx`, `social/notifications.ts`, `social/user-search.ts`. Fix: move the shared pieces into `lib/`.
8. **Smaller items.** About 17 files use untyped `harbor:*` window events (e.g. `harbor:scroll-top`, `harbor:mpv-refresh-geom`); a typed event map would catch renames. `src/lib/debrid/realdebrid.ts` keeps `LIBRARY_CACHE` with a TTL but no size limit. `src/views/player/hdr-stage-bridge.tsx` re-sends unchanged HDR props every second; send on change only. The settings provider keeps three copies of the settings (`useState`, the store and `settingsRef`).
