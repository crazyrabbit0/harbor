# Architecture follow-ups

Findings from the October 2026 architecture review that `fix/architecture-review` did not fix. That branch covers the trust boundary, secrets, settings durability, the Rust/TS episode rule, dead `harbor.site` calls, Play-on pairing, the Cloudflare solver and browser windows, chrome buttons under the CSP, per-client remote replies, credentialed streaming requests, the Memory HUD's fetch wrapper, queued navigation updates, dead mpv listeners, bounded shutdown waits, blocking commands on the main thread, the stremio-server kill, provider calls outside `safeFetch`, `safeFetchLocal`'s local-network grant, the shared dev proxy list, the debrid library caches, the HDR stage's repeated sends, settings writes during render, the shared `safeFetch` blocklist, view definitions, the profile roster, settings migrations, `lib/` → `views/` imports, typed `harbor:*` events, and the mpv bridge split (configuration, session, events, geometry, parsing, subtitles and audio in their own modules).

Each item says what is wrong, where, why it matters, and a suggested fix. Read `AGENTS.md`, `src/AGENTS.md` and `src-tauri/AGENTS.md` first: they list the test traps (source-regex tests, mock `require` lists) that these files are covered by.

## Decided not to fix

- **Torrent engine LAN server** (`src-tauri/src/torrent_engine.rs`, `0.0.0.0:11470`, `/{hash}/create`) has no authentication. Stremio-protocol clients and the Android TV shell (gitignored `android-native/`, not in this repo) call it, so a key would break clients this repo cannot update. Revisit only together with a TV shell release that learns the web remote key.
- **Direct `fetch` calls that stay direct.** After the provider, tracker and AI calls moved to `safeFetch`, the remaining global `fetch(` calls read `blob:`/`data:`/same-origin URLs (avatars, icons, `/spooktober/`, `/manga-img`, `/anime-hero-art.json`, `convertFileSrc` files), talk to the local torrent engine or Stremio server, post `FormData` to Harbor's dead account API, run the stream-plugin sandbox's own `fetch`, send `keepalive` scrobbles that must outlive the page, run only off-Tauri (Modrinth in `games/mods.ts` and `minecraft-catalog.ts`, which use `invoke` in the app), or measure raw download speed (`speed-test-run.ts`). `harbor_fetch` cannot carry `FormData`, `keepalive` or a streamed body, so moving those would break them.

## Structure (refactors, own branch)

1. **`createMpvBridge` still owns `load` (~480 lines in `mpv.ts`).** Configuration (`mpv-config.ts`), the retained Windows session (`mpv-session.ts`), event rules (`mpv-events.ts`, a pure reducer), geometry (`mpv-geometry.ts`), parsing (`mpv-tracks.ts`), subtitles (`mpv-subtitles.ts`), audio (`mpv-audio.ts`) and the stateless property and command forwarders (`mpv-controls.ts`) are separate modules. What remains is `load`'s ordered steps, whose order two tests pin by source position, the effect runner, and the setters that also update the snapshot (volume, mute, speed, seek, HDR-to-SDR); splitting those further would only add indirection. Revisit if `load` grows again. The PiP window is a separate webview playing its own `<video>`, so its `currentTime` is that window's position, not a copy of the mpv one.

## Platform migrations

Each of these has its mechanism and a first converted area in place; the rest moves over one area per branch.

1. **Generated IPC types.** ts-rs exports the mpv commands and `mpv://event` (`mpv_ipc.rs`), `app_features` (`app_features.rs`), the cast commands (`cast/src/cast_ipc.rs`) and the streaming-server status (`cast_server_ipc.rs`) and harbor-core's stream enums (`streams_ipc.rs`, through harbor-core's `ts` feature) and harbor-music's catalog refs, row layouts, connections, track core, source candidates, health, video stream and database bootstrap (`music/src/model.rs` → `music-ipc.ts`) and the torrent engine's command results (`torrent_engine.rs` → `torrent-ipc.ts`) the `harbor_fetch` request and response (`fetch_ipc.rs` → `fetch-ipc.ts`, used by every caller) and nearly every other command result (the games, music, live TV and app modules, about 130 types) to `src/lib/generated/`, and each module's `export_bindings` test fails when its file is stale (see `src-tauri/AGENTS.md`). The settings commands need nothing: they pass opaque JSON strings. Argument structs are generated for the app commands that take one (`proxy_register` → `stream-proxy-ipc.ts`, `media_server_request` → `media-server-ipc.ts`, `harbor_upload` in `fetch-ipc.ts`, `subtitle_credential_bind`, `diagnostics_collect`, `cast_load` → `CastLoadArgs` in `cast-ipc.ts`, and the mpv and `harbor_fetch` arguments) and for the games commands' request structs (cloud and debrid files, public file hosts, transfers, torrents, preparation, saves, Sims, WoW addons, Hydra import and the Minecraft catalog → `games-requests-ipc.ts`). The other command arguments (plain scalar parameters such as `cast_seek`'s `sec` or `games_transfer_action`'s `profile, id, action`), results that are untyped `serde_json::Value` (`games_pokemon` relays the .NET Pokémon engine's JSON and `capstan_install` the extension bridge's, so Rust has no shape to export) and the harbor-core structs (`Stream`, `ParsedStream`, `ScoredStream`, whose `#[serde(flatten)]` maps and TS-only fields have no faithful ts-rs form) still declare their shapes by hand. tauri-specta would also generate the `invoke` wrappers, but its Tauri 2 line is still a release candidate (2.0.0-rc.28 with an exact specta pin) and takes over the single `invoke_handler`; reconsider when it ships a stable 2.x.
2. **Durable user data.** `src/lib/durable-store.ts` mirrors the keys in `DURABLE_PREFIXES` into `user-data.json` (`user_data_read`/`user_data_write`), restoring them into a WebView profile that lost them: the watch-event log, playback history, the watchlist, the six manual watched-mark stores, custom and manga lists, collections, favorites, local Continue Watching, removed local files, ratings with their import receipts, manga reading progress, manga and eBook bookmarks and eBook annotations, hidden episodes, the eBook library, favorites and read-later lists (their inline EPUB covers live in IndexedDB), and saved games, plus the small choices a user makes once and expects back (Games library data, installed addons and their order, Live TV favorites and pins, sports reminders, Discovery saves and blocks, pinned catalogs, layouts, presets, home-server connections, auto-download and kids' progress). Of about 320 keys the app writes, the rest are caches, view toggles, snoozes, scroll positions and session or migration flags, which a cleared WebView can safely lose. Every durable write rewrites the whole file, so bulky values stay out of durable keys: uploaded collection covers live in IndexedDB (`lib/collection-images.ts`) and only their reference reaches the file, and large recomputable caches stay in localStorage or IndexedDB. Once most user data is in the file, backups (`lib/backup.ts`) can read it instead of scanning localStorage.
3. **Rust workspace.** `src-tauri/Cargo.toml` is a workspace with `harbor-shared`, `harbor-games`, `harbor-music`, `harbor-livetv` (DVR and Multiview) and `harbor-cast` (Chromecast, DLNA, Roku and AirPlay), each behind a default feature of the same name. The app routes `games_*`, `music_*`, `dvr_*` and `multiview_*` commands, plus the exact names `harbor_cast::handles` lists, to each crate's `invoke_handler()` (`route_commands`), and `app_features` tells the frontend which rooms to hide. The crates reach app code only through `harbor-shared`: the mpv helpers (`harbor_shared::mpv`, feature `mpv`), `FetchHook`, `AppHooks` (secrets, ffmpeg lookup, yt-dlp, asset scope) and `CastHooks` (stream proxy registration, HLS and audio sessions, subtitle burn-in, ffmpeg) as managed state, with the cast payloads in `harbor_shared::cast_types`. The stream proxy, HLS and audio cast servers, `cast_subs.rs` and `transcode.rs` stay in the app because other modules use them.
4. **Typecheck speed.** CI runs `typecheck:fast` (TypeScript 7, about 15 s) next to the TypeScript 5.8 check (about 2 min). The locale modules are not the slow part: checking all 2,294 locale files alone takes under 5 s of the 113 s run, and each locale already loads lazily, so converting them to JSON would only break the Crowdin and `check-i18n` tooling that parses them. The TypeScript 5.8 check can go once the language server works with TypeScript 7 (7.0.2 ships no `tsserver.js`, and neither does the 7.1 dev build on `typescript@next`).
5. **React Compiler.** It compiles the folders in `REACT_COMPILER_DIRS` (`vite.config.ts`): all of `src/components/`, `src/chrome/` and `src/views/`. The player reads its bridge during render through `usePlayerBridgeSlot()` (`views/player/hooks/use-player-bridge.ts`), whose ref is a getter/setter that also updates a render-time `bridge`; `VideoAudioCast` is wired in a layout effect through `connect(receiver, bridgeSlot, snapshot)`; the music room keeps its navigation counters and trail in one `MusicNavState` object. `src/lib/` and the other entry files (`App.tsx`, `main*.tsx`) are not compiled. `music-virtual-track-list.tsx`, `virtual-grid.tsx` and `manga-detail/chapter-list.tsx` declare `"use no memo"` because `useVirtualizer` (`@tanstack/react-virtual`) is an incompatible library; `check:react-compiler` lists them as opted out. A dynamic `import()` inside a component is not lowered, so loaders sit at module scope (`const loadX = () => import(...)`) and the component calls them. The compiler keys a memo on what its callback reads, not on the dependency array, so a dependency the body never reads (a store version, or `void version;`) is dropped; such memos go through `readAtVersion(version, () => ...)` (`lib/read-at-version.ts`), and `check:react-compiler` fails on any `useMemo`/`useCallback` dependency its body does not read. Add a folder or file after `pnpm check:react-compiler <path>` reports no skipped component; a skip usually means a `try`/`finally`, a conditional inside `try`, or a disabled `react-hooks` rule, which a promise chain or a dependency-complete effect removes. There are about 4,000 `useEffect` call sites, and hand-written `useMemo`/`useCallback` (about 2,000 in the compiled folders) can go once a folder is compiled and verified. `vp check` enforces oxlint's React Compiler rules on the compiled folders as errors (`REACT_COMPILER_RULES` in `vite.config.ts`: `refs`, `immutability`, `static-components`, `set-state-in-render`, `purity`, `globals`, `use-memo`, `void-use-memo`, `preserve-manual-memoization`, `error-boundaries`), and CI runs it on every changed file. A clock read during render goes through `useNow(intervalMs, active)` (`lib/use-now.ts`) when it must tick, or `useState(Date.now)` when the moment the view opened is enough; a random seed is a `useState` initializer. The rule also flags `Date.now()` inside some event handlers and async callbacks, which carry an `oxlint-disable-next-line react/purity` naming where they run. Two stay off (`REACT_COMPILER_RULES_OFF`): `set-state-in-effect` (about 1,180 call sites, mostly resets on a key change or a loading flag set before a fetch) and `incompatible-library` (the three `useVirtualizer` files above, already opted out); `react-hooks/exhaustive-deps` is off there too (about 500 warnings), since the compiler ignores dependency arrays and `check:react-compiler` checks memo dependencies. Turn each on once its call sites are converted. `src/lib/` and `src/hooks/` are not linted for these rules, since they are not compiled (their settings, view and game hooks read refs during render on purpose).
