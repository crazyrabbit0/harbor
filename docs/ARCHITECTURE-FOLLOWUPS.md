# Architecture follow-ups

Findings from the October 2026 architecture review that `fix/architecture-review` did not fix. That branch covers the trust boundary, secrets, settings durability, the Rust/TS episode rule, dead `harbor.site` calls, Play-on pairing, the Cloudflare solver and browser windows, chrome buttons under the CSP, per-client remote replies, credentialed streaming requests, the Memory HUD's fetch wrapper, queued navigation updates, dead mpv listeners, bounded shutdown waits, blocking commands on the main thread, the stremio-server kill, provider calls outside `safeFetch`, `safeFetchLocal`'s local-network grant, the shared dev proxy list, the debrid library caches, the HDR stage's repeated sends, settings writes during render, the shared `safeFetch` blocklist, view definitions, the profile roster, settings migrations, `lib/` → `views/` imports, typed `harbor:*` events, and the mpv bridge split (configuration, session, events, geometry, parsing, subtitles and audio in their own modules).

Each item says what is wrong, where, why it matters, and a suggested fix. Read `AGENTS.md`, `src/AGENTS.md` and `src-tauri/AGENTS.md` first: they list the test traps (source-regex tests, mock `require` lists) that these files are covered by.

## Decided not to fix

- **Torrent engine LAN server** (`src-tauri/src/torrent_engine.rs`, `0.0.0.0:11470`, `/{hash}/create`) has no authentication. Stremio-protocol clients and the Android TV shell (gitignored `android-native/`, not in this repo) call it, so a key would break clients this repo cannot update. Revisit only together with a TV shell release that learns the web remote key.
- **Direct `fetch` calls that stay direct.** After the provider, tracker and AI calls moved to `safeFetch`, the remaining global `fetch(` calls read `blob:`/`data:`/same-origin URLs (avatars, icons, `/spooktober/`, `/manga-img`, `/anime-hero-art.json`, `convertFileSrc` files), talk to the local torrent engine or Stremio server, post `FormData` to Harbor's dead account API, run the stream-plugin sandbox's own `fetch`, send `keepalive` scrobbles that must outlive the page, run only off-Tauri (Modrinth in `games/mods.ts` and `minecraft-catalog.ts`, which use `invoke` in the app), or measure raw download speed (`speed-test-run.ts`). `harbor_fetch` cannot carry `FormData`, `keepalive` or a streamed body, so moving those would break them.

## Structure (refactors, own branch)

1. **`createMpvBridge` still owns `load` (~480 lines in `mpv.ts`).** Configuration (`mpv-config.ts`), the retained Windows session (`mpv-session.ts`), event rules (`mpv-events.ts`, a pure reducer), geometry (`mpv-geometry.ts`), parsing (`mpv-tracks.ts`), subtitles (`mpv-subtitles.ts`), audio (`mpv-audio.ts`) and the stateless property and command forwarders (`mpv-controls.ts`) are separate modules. What remains is `load`'s ordered steps, whose order two tests pin by source position, the effect runner, and the setters that also update the snapshot (volume, mute, speed, seek, HDR-to-SDR); splitting those further would only add indirection. Revisit if `load` grows again. The PiP window is a separate webview playing its own `<video>`, so its `currentTime` is that window's position, not a copy of the mpv one.

## Platform migrations

Each of these has its mechanism and a first converted area in place; the rest moves over one area per branch.

1. **Generated IPC types.** ts-rs exports the mpv commands and `mpv://event` (`mpv_ipc.rs`), `app_features` (`app_features.rs`), the cast commands (`cast/src/cast_ipc.rs`) and the streaming-server status (`cast_server_ipc.rs`) and harbor-core's stream enums (`streams_ipc.rs`, through harbor-core's `ts` feature) and harbor-music's catalog refs, row layouts, connections, track core, source candidates, health, video stream and database bootstrap (`music/src/model.rs` → `music-ipc.ts`) and the torrent engine's command results (`torrent_engine.rs` → `torrent-ipc.ts`) to `src/lib/generated/`, and each module's `export_bindings` test fails when its file is stale (see `src-tauri/AGENTS.md`). The settings commands need nothing: they pass opaque JSON strings. The other ~500 commands and the harbor-core structs (`Stream`, `ParsedStream`, `ScoredStream`, whose `#[serde(flatten)]` maps and TS-only fields have no faithful ts-rs form) still declare their shapes by hand on each side. Music commands take scalar arguments or those generated structs, so music needs nothing more. tauri-specta would also generate the `invoke` wrappers, but its Tauri 2 line is still a release candidate (2.0.0-rc.26 with an exact specta pin) and takes over the single `invoke_handler`; reconsider when it ships a stable 2.x.
2. **Durable user data.** `src/lib/durable-store.ts` mirrors the keys in `DURABLE_PREFIXES` into `user-data.json` (`user_data_read`/`user_data_write`), restoring them into a WebView profile that lost them: the watch-event log, playback history, the watchlist, the six manual watched-mark stores, custom and manga lists, collections, favorites, local Continue Watching and removed local files. About 970 `localStorage.` call sites remain, mostly caches and preferences. Every durable write rewrites the whole file, so bulky values stay out of durable keys: uploaded collection covers live in IndexedDB (`lib/collection-images.ts`) and only their reference reaches the file, and large recomputable caches stay in localStorage or IndexedDB. Once most user data is in the file, backups (`lib/backup.ts`) can read it instead of scanning localStorage.
3. **Rust workspace.** `src-tauri/Cargo.toml` is a workspace with `harbor-shared`, `harbor-games`, `harbor-music`, `harbor-livetv` (DVR and Multiview) and `harbor-cast` (Chromecast, DLNA, Roku and AirPlay), each behind a default feature of the same name. The app routes `games_*`, `music_*`, `dvr_*` and `multiview_*` commands, plus the exact names `harbor_cast::handles` lists, to each crate's `invoke_handler()` (`route_commands`), and `app_features` tells the frontend which rooms to hide. The crates reach app code only through `harbor-shared`: the mpv helpers (`harbor_shared::mpv`, feature `mpv`), `FetchHook`, `AppHooks` (secrets, ffmpeg lookup, yt-dlp, asset scope) and `CastHooks` (stream proxy registration, HLS and audio sessions, subtitle burn-in, ffmpeg) as managed state, with the cast payloads in `harbor_shared::cast_types`. The stream proxy, HLS and audio cast servers, `cast_subs.rs` and `transcode.rs` stay in the app because other modules use them.
4. **Typecheck speed.** CI runs `typecheck:fast` (TypeScript 7, about 15 s) next to the TypeScript 5.8 check (about 2 min). The locale modules are not the slow part: checking all 2,294 locale files alone takes under 5 s of the 113 s run, and each locale already loads lazily, so converting them to JSON would only break the Crowdin and `check-i18n` tooling that parses them. The TypeScript 5.8 check can go once the language server works with TypeScript 7 (7.0.2 ships no `tsserver.js`).
5. **React Compiler.** It compiles the folders in `REACT_COMPILER_DIRS` (`vite.config.ts`): all of `src/components/`, `src/chrome/` and `src/views/`. The player reads its bridge during render through `usePlayerBridgeSlot()` (`views/player/hooks/use-player-bridge.ts`), whose ref is a getter/setter that also updates a render-time `bridge`; `VideoAudioCast` is wired in a layout effect through `connect(receiver, bridgeSlot, snapshot)`; the music room keeps its navigation counters and trail in one `MusicNavState` object. `src/lib/` and the other entry files (`App.tsx`, `main*.tsx`) are not compiled. `music-virtual-track-list.tsx`, `virtual-grid.tsx` and `manga-detail/chapter-list.tsx` declare `"use no memo"` because `useVirtualizer` (`@tanstack/react-virtual`) is an incompatible library; `check:react-compiler` lists them as opted out. A dynamic `import()` inside a component is not lowered, so loaders sit at module scope (`const loadX = () => import(...)`) and the component calls them. The compiler keys a memo on what its callback reads, not on the dependency array, so a dependency the body never reads (a store version, or `void version;`) is dropped; such memos go through `readAtVersion(version, () => ...)` (`lib/read-at-version.ts`), and `check:react-compiler` fails on any `useMemo`/`useCallback` dependency its body does not read. Add a folder or file after `pnpm check:react-compiler <path>` reports no skipped component; a skip usually means a `try`/`finally`, a conditional inside `try`, or a disabled `react-hooks` rule, which a promise chain or a dependency-complete effect removes. There are about 4,000 `useEffect` call sites, and hand-written `useMemo`/`useCallback` can go once a folder is compiled and verified. No lint rule enforces the Rules of React yet: `vp check` (oxlint) has no React Compiler rules, and `eslint-plugin-react-hooks` 7 would mean adding ESLint.
6. **Source-text test pins.** About 300 test files read a module's source with `readFileSync` and match it with regular expressions, so a rename breaks them while a real behavior change can pass. The watch log (`tests/activity-watch-events.test.ts`), `mpv-config.ts` (`tests/mpv-config.test.ts`, `monitor-feature-contract`, `playback-critical-path`, `player-startup-readiness`), focus-return resume (`player-focus-resume`, through `hookHarness`), video zoom (`player-video-zoom`, which runs `useVideoFill`) the movie rewatch rules (`rewatch-cw-persistence`, through the playback persistence harness), subtitle auto-sync triggering (`autosync-switch-retrigger`), the slow-load pill (`stream-pill-false-stall`), selected-subtitle caching (`subtitle-selection-cache`), capture folders (`capture-folders`), jump-mark chrome and frame prefetch (`jump-marks`), stream-swap filenames (`subtitle-stream-filename`) and anime tracker identity sync (`cw-anime-sync-ids`), remembered-subtitle restore and credential rebinding (`subtitle-memory-source`, through `restoreHarness`, which runs the restore effect cut out of `use-track-autoload`) and the SDH filter (`subtitle-sdh-filter`: gate, mpv properties, untouched parsed and prepared cues, and read-time stripping in the html5 bridge through `html5-bridge-harness`) are checked by behavior; the pins left in those files read Rust sources, `player.tsx`, the keyboard shortcuts and other modules too large to evaluate. `subtitle-player-lifecycle`, `subtitle-track-metadata`, `player-initial-volume` and `player-interaction-lock` still read the html5 bridge as text and can move to `html5-bridge-harness`. `hookHarness` mocks `useCallback` and `useLayoutEffect` as well, and renders JSX components when the test supplies `react/jsx-runtime`.
