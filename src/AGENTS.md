# src/ (frontend)

Notes for agents working in this folder. Root rules live in `../AGENTS.md`.

## Entrypoints

- `main.tsx` picks the app by Tauri window label or `?harbor-*=1` query: PiP, video-PiP, modal overlay, HDR overlay, DJ deck, captions, `/remote`/`/reader` (phone `MobileShell`), else `App`. Secondary Rust windows load the same bundle; adding a window means a branch here, and its app is a dynamic `import()` there, never a static import, so the main window never parses it.

## Startup bundle

- Everything `main.tsx` and `App.tsx` reach through static imports is parsed before the first screen (the main chunk is ~3 MB). Keep large or rarely used code behind a dynamic `import()` at its point of use. To see why a module is in the main chunk, build with `vite build --sourcemap` (needs `NODE_OPTIONS=--max-old-space-size=12288`, it runs out of memory at the default) and walk the static import chain back to `main.tsx`.
- hls.js and mpegts.js load through `lib/player/stream-libs.ts`, lottie-web through `lib/lottie.ts` (`withLottie` takes a `cancelled` check for effects that unmount first). Never `import lottie`/`import Hls` statically, and never import lucide's whole `icons` map (it pulls every icon in): use `SetIcon` or named icons. `tests/startup-bundle.test.ts` guards these.
- Only the default `Sidebar`/`Topbar` chrome ships in the main chunk: the other layouts (`chrome/dracula-sidebar`, `topdock`, `minui-dock`, …) and `GameRouteLoading` with its games CSS are `lazyView` imports in `App.tsx`. The awards table loads in an idle slot once a `useBundledAwardsVersion()` caller mounts (Big Picture calls `ensureBundledAwards` itself), so a launch that shows no award UI never parses it. `main.tsx` waits for custom themes before the first render only when the stored preset is a `user:` theme.
- tldts (`lib/same-site-host.ts`), the stream plugin adapter and fflate (`loadSubtitleUnzip` in `lib/subtitles/prepare.ts`) are dynamic imports at their point of use, and the Spooktober loading scene is a `lazy()` fallback; keep plugin, subtitle-archive and seasonal code off the main chunk's static graph.
- When profiling playback, use a clip of 45 minutes or more: local Continue Watching notifies on each 1% of progress (`progressBucket` in `lib/local-cw.ts`), so on a 400 s clip every 4 s autosave tick redraws the parked Home page, which real episodes do only about every 27 s.
- `safeFetch` shares identical concurrent string-URL GETs in Tauri (`dedupedGet`, keyed by URL and headers, each caller gets a `clone()`); a request with a `signal`, a body or `cache: "no-store"` never shares.
- The flag-icons sheet (`components/flag.tsx`), music dock, Quick Library dock and nav/loader Lottie data load after first paint or on first use; optional lazy chrome sits in `SilentBoundary` so a failed chunk renders nothing instead of the crash screen. Module-level stores read localStorage/IndexedDB on first use through a lazy getter, never at import; `tests/startup-bundle.test.ts` guards both.
- `idb-cache.ts` caps only `TRIMMABLE_PREFIXES` (Cinemeta metas, TMDB catalog pages and per-title detail bundles, ani.zip mappings, addon catalog rows and addon movie/series metas, IMDb title ratings, stremio-addons) at 2000 entries; a trimmable write counts the store only once its running upper bound reaches the cap; anything else in that store (music pins, Liquipedia index, rank snapshots) is never evicted, so a new refetchable cache adds its prefix there.
- Installed-addon catalog rows (30 min) and metas (movies 3 h, series 30 min; a 404 or an explicit `{"meta": null}` for 12 h) persist in IndexedDB through `addon-catalog-cache.ts`, keyed by URL plus the addon Accept-Language. The disk copy answers only the first read of a key per session, so later misses refetch as before. A disk meta past its TTL but under 24 h (`META_STALE_MS`) is served at once and refreshed in the background, one every 400 ms starting 20 s after launch. ani.zip mappings persist 12 h (a 404 for 3 h). Failures and timeouts are never stored.
- Tracker reads at launch are gated on each service's activity watermark. Trakt `sync/last_activities` is asked at most every 20 s (`lib/trakt/activities.ts`), and the watchlist, history and calendar are reused from IndexedDB (`trakt.sync.v1:`) while their watermark is unchanged; recommendations keep 6 h. Simkl `all-items` lists persist under `simkl.allitems.v1:` while `sync/activities` is unchanged (`lib/simkl/activities/disk.ts`). Any Trakt/Simkl write resets the gate (`onTraktWrite`/`onSimklWrite`).
- External Continue Watching (`lib/feed/external-cw.ts`) compares sessions by access token, so the secrets-ready re-read of the same account does not refetch playback progress, and one tracker's account change reuses the other tracker's list if it is under 30 s old.
- The Games background Steam scan waits 15 s after launch (`PRIME_DELAY_MS`, `views/games/game-access-context.tsx`).
- Each Tauri command costs a CORS preflight about every 5 s: Tauri's `ipc://` responses set no `Access-Control-Max-Age` and `app.security.headers` does not apply to that protocol, so the ~50 OPTIONS per launch can't be removed without patching Tauri.
- Code outside `SettingsProvider` reads the `harbor.settings` mirror through `storedSettings()` (`lib/stored-settings.ts`), which parses it once per change. Per-card and per-fetch helpers must not `JSON.parse(localStorage.getItem(...))` large keys themselves; Discover spent ~80 ms per open re-parsing settings and the 0.5 MB `harbor.anidbtvdbcache`.
- `Row` (`components/row.tsx`) draws skeletons until the row comes within 600 px and keeps cards lazy per column. `alwaysActive` disables that for the whole row; use it only for rows whose children must exist (loading skeletons), not for static tile rows.
- `useView()` re-renders its caller on every navigation, and kept-alive pages (Home, Discover…) stay mounted, so every card and row under them redraws on each page change. Components that only call actions (`openMeta`, `openPicker`, `setView`, row/scroll memory) use `useViewActions()`, whose value never changes; a new action on `ViewValue` must be a stable callback and be listed in `VIEW_ACTION_KEYS`. Always-mounted chrome (top bar, sidebars, docks, search, hover preview) reads state through `useViewSelector((v) => ({ ... }))`, which re-renders only when a selected field changes; select booleans (`pickerTop: v.topKind === "picker"`) rather than `topKind`/`view` when that is all it needs. App.tsx wraps those chrome components in `memo`, so pass them only primitive props. A parked page (`[data-layer-inactive]`, `content-visibility: hidden`) reports every element as off-screen, so visibility observers (`Poster` release, `Row` near/far, `LazyChild`, the Discover `Rail`) ignore "left the viewport" there; otherwise showing the page again redraws every card and reloads its images. `Shell` itself re-renders on every navigation, so pages from `lazyView` (and `SpooktoberHome`) are `memo`'d, and `CustomizableRows`/`CatalogRows` too: a page prop or row prop built inline (`{{...}}`, `() => ...`, `[...]`, JSX) defeats that and redraws every row. `useT()` returns the same function until the language, region or catalog changes, and `useCwAdvance` returns its previous array when the list is unchanged.
- The library calendar keeps each resolved show and movie in `harbor.calendar.resolved.v1` (12 h, misses 30 min; `lib/calendar-library.ts`). Cinemeta goes first since it is one request, a run dated as closed ("2008–2013") or a movie two or more years old stops there, and TMDB (3-4 requests per show) runs only when Cinemeta has nothing.
- `main-tv.tsx` mounts `views/big-picture/bp-tv-app.tsx` (Android TV). Never import it from `main.tsx`.
- `retro-main.tsx` is the `retro-player.html` entry (game popout).

## Views and navigation

- Code outside `ProfilesProvider` reads the stored profile list (`harbor.profiles.v1`) only through `lib/profile-roster.ts` (`readRoster`, `activeSettingsSource`, `separateProfileKey`, `stremioDataProfileId`, ...), which parses it once per change. Harnesses that mock `require` pass `profileRosterFor(storage)` from `tests/helpers/profile-roster.ts`.
- Every `harbor:*` window event is declared with its payload in `HarborEventMap` (`lib/harbor-events.ts`), which extends `WindowEventMap`, so listeners get a typed `e.detail`; `tests/harbor-events.test.ts` fails on an undeclared or unused name. Dispatch new events with `emitHarborEvent(name, detail)`.
- `lib/` never imports from `views/` (`tests/lib-layering.test.ts`). Types, stores and helpers that both need live in `lib/` (`lib/home/home-types.ts`, `lib/social/profile-api.ts`, `lib/big-picture/bp-play-request.ts`, `lib/settings/section-id.ts`, ...), and views import them from there.
- Adding a view: add it to the `View` union and the `Frame` union (`lib/view-types.ts`), map its frame in `VIEW_OF_FRAME` and add a `frameKey()` case (`lib/view.tsx`; `setView` starts a fresh root for any room except Downloads and Settings), then add an import fn plus a `lazyView(...)` wrapper in `App.tsx` and its render branch in `Shell`. Optionally add it to the `useViewPreloader` idle-prefetch list, which starts 8 s after launch and loads one batch per idle slot at least 1.5 s apart, so view chunks never compete with startup fetches.
- `setView` pushes a `Frame` onto a stack and resets scroll memory. Use the existing frame kinds (`meta`, `person`, `player`, ...) for detail-like pages instead of new views.
- In `ViewProvider`, `stackRef`/`forwardStackRef` are the source of truth: `setNavStack`, `pop` and `goForward` compute the next stack from them at call time and then `setStack` the result. Never pass React a functional updater for the stack, since a queued updater runs later (twice under StrictMode) and its side effects, like clearing scroll memory, would repeat.

## Tauri bridge

- There is no wrapper module; files import `@tauri-apps/api/core` `invoke`/`listen` directly, and every call needs a non-Tauri guard (`isTauri()` or `"__TAURI_INTERNALS__" in window`), since the same code runs in a browser.
- plugin-fs and `convertFileSrc` reach only the standard dirs plus folders granted at runtime (`src-tauri/AGENTS.md`). A user-chosen folder or file kept outside settings.json must be listed in `collectStoredPaths` (`lib/fs-scope.ts`), and a folder read recursively needs `allowFsPaths([picked])` right after the dialog: the dialog grants the fs scope only the folder's direct children, and a drag-drop grants no asset access.
- mpv state arrives only via `listen("mpv://event")` in `lib/player/mpv.ts` (`property-change`, `end-file`, `file-loaded`, `playback-restart`, synthetic `player-failure`). The UI contract is `PlayerBridge`/`PlayerSnapshot` in `lib/player/bridge.ts`. A property that maps one-to-one onto the snapshot goes in `applyMpvProperty` (`lib/player/mpv-tracks.ts`, unit-tested in `tests/mpv-tracks.test.ts`). Each event goes through `reduceMpvEvent` (`mpv-events.ts`), which returns the next state plus effects that `runEventEffect` in `mpv.ts` executes in order; a new lifecycle rule goes in the reducer with a test in `tests/mpv-events.test.ts`, and anything that calls mpv or touches subtitles/audio becomes an effect. Pure mpv configuration (start args, HDR-to-SDR properties, buffer phases, the reuse key) lives in `mpv-config.ts` (unit-tested in `tests/mpv-config.test.ts`), the Windows mpv session one player keeps for the next in `mpv-session.ts`, subtitle state and selection in `mpv-subtitles.ts`, audio filters and output reloads in `mpv-audio.ts`, embed geometry in `mpv-geometry.ts`; each reads the bridge's `snap`/`mediaRevision` through getters, since `snap` is reassigned on failure. `tests/helpers/mpv-bridge-harness.ts` compiles these modules for real against its mocks, so a new import in any of them needs a mock there; source-regex tests on that code read the module it lives in.

## Player and streams

- Engine choice is `pickBridge` (`views/player/player-utils.ts`): `mpv` falls back to `html5` when `probeMpv()` fails, `auto` tries mpv first in Tauri. In the player, hls.js and mpegts.js run only inside the html5 engine (`lib/player/html5/bridge.ts`); Multiview has its own hls/mpegts/native tiles (`views/multiview/multi-player.tsx`). Controls branch on `ctx.engine`, so a new control must say what it does on html5.
- Play flow: `usePipelineResult` → `runPipeline` (`lib/streams/pipeline.ts`) → `resolveStream`/`resolveViaDebrids` (`resolve.ts`) → `usePickHandler` classifies `p2p`/`direct`/`debrid` → `openPlayer` (`views/play-picker/use-pick-handler.ts`). Autoplay walks candidates in `use-auto-fire.ts`/`use-auto-candidates.ts`.
- Player behaviour lives in `views/player/hooks/` (~70 hooks); overlays are `views/player/*-layer.tsx` composed by `player-overlay-layers.tsx`. The HUD layout editor is `views/settings/player-layout-panel/`, rendered by `components/player/transport/control-renderer*.tsx`. Big Picture has its own player (`views/big-picture/player/`).
- Every playback hotkey gives on-screen feedback. Volume and speed have their own HUD cards and subtitle delay its own readout; everything else goes through the action HUD (`components/player/action-indicator.tsx`, same glass card and slot as the speed HUD), fed by `showActionFeedback` in `views/player.tsx` and passed to `useVideoFill` and `useKeyboardShortcuts` as `onOsd`. A new hotkey passes `{ icon, title, value }`, with translated title and value naming the state it reached (`Seek` / `+10s`, `Subtitles` / `English`). Volume, speed and action cards hide each other, and any card in the top slot hides the Anime4K and SVP badges. Anime4K changes flash only while `playerAnime4kIndicator` is off, since the badge already shows the mode.
- Ctrl+=, Ctrl+- and Ctrl+0 scale the interface everywhere, the player included (`App.tsx`); don't give a player hotkey a Ctrl+digit or Ctrl+= default.
- `NextEpisodePrefetch` (`views/player/next-episode-prefetch.tsx`) runs the stream pipeline for the next aired episode once the current one shows its first frame, and stores it in the picker cache under the picker's own config hash, so Next and auto-advance find their streams ready. It skips plugins unless `pluginsBackground` is on (the entry is then stored as incomplete and the picker still asks them), and opens the top debrid link only in the last 90 s and only with `instantPlaybackPreparation` on. `keepPrefetchedPickerCache` keeps that one entry through the aggressive sweep that runs when the player unmounts.
- The in-player stream switcher always opens in place; never navigate to the full picker from it (`use-stream-switcher.ts`). A start that never plays is abandoned after `NEVER_STARTED_CEILING_MS` (45 s, `player-utils.ts`, enforced in `use-auto-retry.ts`; its separate 75 s never-started stall grace only decides when a retry fires). A recovery belongs to the load that failed, never to a later source or bridge (`use-auto-retry.ts`).
- `lib/player/mpv-audio.ts` reloads mpv's audio output on Windows, while playing or paused, after any `audio-device-list` change, when the app becomes visible, and on refocus after 60 s away. mpv's own WASAPI re-root can leave audio on a gone endpoint (HDMI <-> Bluetooth differ in rate and format), and sleep or a screensaver can release the endpoint without a hotplug event (a screensaver never hides the document). The reload re-asserts the device, runs `ao-reload`, reselects the audio track mpv dropped, and with normalization on seeks in place so dynaudnorm refills.
- Opening at saved progress restarts from 0 only at `RESTART_THRESHOLD` (`use-bridge-load.ts` and `lib/player/resume-start.ts`). It must equal `WATCHED_RATIO` (0.85, `use-resume-autosave.ts`). With any lower value, an episode left between the two ratios stays in Continue Watching but restarts, and auto-skip then lands it just after the intro.

## Detail page episode lists

- The page scroller is `scrollRef` in `views/detail.tsx`; `useScrollMemory` restores its position on entry when `resumeDetailScroll` is on, so a scroll you add must not fight a restored position.
- Episode rows carry `data-ep` (episode number) and, for anime, `data-epid`; scroll to those rather than by index. List rows use `content-visibility: auto`, so offsets shift while rows render and a one-shot scroll lands wrong; keep re-aligning until layout settles (`views/detail/use-episode-auto-scroll.ts`).
- The anime episode section is rebuilt, not just re-rendered, when `animeDetails`' `enrichPromise` resolves (`setAnimeEpisodes` in `detail.tsx`), so component state and refs inside it reset mid-visit. State that must survive that rebuild has to live outside the component.

## Anime tracker sync (MAL / AniList / Stremio / Simkl)

- `PlayEpisode` objects for tt ids reached by Next, the queue or Continue Watching are built from Cinemeta (`loadCinemetaEpisodes` in `lib/series-episodes.ts`). They carry only TVDB `season`/`episode`: no `imdbSeason`/`imdbEpisode` and no `kitsuStreamId`. Any sync gated on `imdbSeason` silently skips them, and a fallback that sends `episode` hands MAL/AniList a TVDB number (9) instead of the entry number (186). `record()` in `views/player/hooks/use-resume-autosave.ts` builds `syncEpisode` for this. The Simkl code (`lib/simkl/scrobble.ts`, `record-watched.ts`) uses the same defaulting.
- Multi-season entries (one Kitsu/MAL entry spread over several TVDB seasons, e.g. Reborn) are numbered by `absoluteEntryNumber` in `lib/anime-entry-target.ts`. AniZip episode keys drift from absolute numbering in places (Reborn around S4E23-25 and S7E14-16), so don't treat `resolveAnimeIdentity`'s `number` as the episode for these entries.
- `setEpisodesWatchedStremio` returns `null` to mean a deliberate skip, and callers treat that as success with no retry. Detected anime on a tt id is skipped unless it passes explicit `season:imdbEpisode` keys, so a missing IMDb pair means the Stremio push silently never happens.
- Simkl answers a repeated `scrobble/stop` with 409 and a show episode already in history with `added.episodes: 0` and an empty `not_found`; both count as delivered, otherwise `lib/simkl/pending-sync.ts` replays the same watches on every launch. `anime-detect.ts` keeps each not-anime verdict with its own expiry (14 days, 1 day when Cinemeta has no record), so the list never lapses at once and re-asks ani.zip about every title.
- Trakt and Simkl clients share one in-flight request for identical concurrent GETs (per token, and per profile for Simkl); writes are never merged.
- When debugging, the MAL/AniList "sent" map (`harbor.mal.synced.v1.<profile>`, key `harborId|season|ep`) stores the tracker's CURRENT count as `p` when the target was at or below it. A record of `…|8|9 -> 185` therefore means Harbor sent episode 9 and the call did nothing. It does not mean Harbor sent 185.

## Settings

- A new setting touches `lib/settings/types.ts` (type), `lib/settings/defaults.ts` (`DEFAULT`), and usually a sanitizer in `lib/settings/load.ts`. A one-time change to existing users' values is a new entry appended to `SETTINGS_MIGRATIONS` (`lib/settings/migrations.ts`); the blob records `_schemaVersion` plus each migration's flag, which older builds still read, so never reorder or remove an entry. If user-facing, also add a `SETTINGS_OPTIONS` entry in `views/settings/nav.tsx`.
- `SETTINGS_OPTIONS` is parsed by `scripts/settings-search-entries.mjs` via the TS AST: keep it a static array of string-literal objects (no spreads, no computed values).
- Settings dialogs must portal and sit above the title bar's z-index 140; `pnpm check:settings` enforces this. Run `check:search` after changing labels or keywords.
- A new settings page needs a `SectionId` (`views/settings/shared.tsx`), a `lazy()` panel plus `SECTION_PRELOAD` entry in `views/settings.tsx`, a group in `views/settings/groups.ts` (`TOP_GROUPS`), and tabs, if any, in `tab-registry.ts` (`SECTION_TABS`).
- Row primitives come in three sets (`ui.tsx` `SRow`/`SCard`, `kit.tsx` `SettingRow`/`SettingGroup`, `shared.tsx` `ToggleRow`); match the siblings in the panel you edit. Search jumps land on `SettingGroup`'s `settingsAnchor(label)` id.
- `check:settings` also fails on overlays without Escape/backdrop/close, a `Settings` key missing from `defaults.ts`, a key written from settings UI but never read elsewhere (`src-tauri/src` counts), ALL-CAPS labels, and unreferenced or duplicate keyframes.
- Components read settings through `useSettingsSelector((s) => ({ ... }))`, selecting only the fields they use, and take `update` from `useSettingsUpdate()` (`switchProfile`/`toggleStreaming` from `useSettingsActions()`); `useSettings()` re-renders its caller on every settings change. Effects and callbacks that need the whole object, or pass it to a builder (`buildTmdbRows`, `animeDetails`, `runWebhookTick`), read `useSettingsGetter()()` instead of keeping a `settingsRef`; Only the Settings panels, Big Picture, components that pass the whole object on, and modules a test loads with a `useSettings`-only mock still call `useSettings()`; a test that mocks `@/lib/settings` needs `useSettingsSelector` too once its module uses it. `update` returns the same state when every patched value is unchanged, so a no-op patch renders and persists nothing.
- Every change inside `SettingsProvider` goes through its `setSettings`, built by `createSettingsWriter` (`lib/settings/settings-writer.ts`): it keeps the latest settings and pushes `tmdbLanguage` and the TMDB/TVDB/Trakt/MAL/IGDB keys to their module setters before the React update, so children rendering in that pass (memo keys, "is configured" checks) already read the new value. Never call `setReactSettings` directly.
- Playlists live only in `lib/iptv/playlists-store.ts` (`usePlaylists`/`writePlaylists`); `settings.iptvPlaylists` is a legacy field that `migrateLegacyPlaylists` (run once in `main.tsx`) merges into the store and strips from every settings blob. Settings persist at once, and a burst of changes (a slider drag) writes its latest value at most every 150 ms, flushed on `pagehide`, `beforeunload` and hidden visibility.
- Persistence: localStorage `harbor.settings.<profileId>` (or `harbor.settings.shared` when linked, mirrored to `harbor.settings`), then `settings_write` to `settings.json` debounced 600 ms; tracker/server session keys go to `secrets.json` through `lib/secret-store.ts`, scoped `<prefix>.<profileId>`. Provider keys in `SECRET_SETTING_KEYS` (`lib/settings/secret-fields.ts`) never reach the blob or settings.json: `serializeSettings` strips them, they live in `harbor.settings-secrets.v1.<shared|profileId>` (the blob's own scope), `loadEffective` merges them back, and once secrets settle `persistEffective` moves any still in a blob into the store. Code outside `SettingsProvider` reads `tmdbKey` through `getTmdbKey()` (`lib/settings/tmdb-key.ts`, set by the provider, else `loadEffective`), never from the mirror. A failed `secrets_write` logs `[secrets] secrets_write failed`, shows in `getSecretsWriteStatus`/`subscribeSecretsWriteStatus` (`lib/secret-store.ts`) and retries after 1 s, 5 s, then every 30 s; the blob and the IPTV list keep their secrets until `secretsDurable()` (every secret set so far written by a successful `secrets_write`), `subscribeSecretsDurable` strips them once the write lands, and leaving the page also calls `flushSecrets`. `SECRET_NESTED_PATHS` (`webhooks.discordUrl`/`webhooks.telegramUrl`) follow the same rules, stored under their dotted path. Xtream logins and typed M3U/EPG URLs that embed credentials live in the secret key `harbor.iptv.credentials.v1` (`{[playlistId]: {username?, password?, url?, epgUrl?, epgBuilt?}}`, not profile-scoped, backup section `iptvCredentials`). Once they are durable, `lib/iptv/playlists-store.ts` strips logins and the URLs built from them out of `harbor.iptv.playlists.v1`, and stores typed URLs redacted (`redactUrl` in `lib/iptv/url-credentials.ts`: userinfo and the values of `user`, `username`, `pass`, `password`, `passwd`, `pwd`, `token`, `access_token`, `auth_token`, `key`, `apikey`, `api_key` become `***`). `readPlaylists`/`usePlaylists` join the full URLs back, so caches keyed on the URL keep their keys, and an Xtream EPG is rebuilt only when its entry carries `epgBuilt`. A backup without `iptvCredentials` leaves out every playlist that needs a login. A failed `settings_write` logs a `[settings]` error and is exposed through `getSettingsWriteStatus`/`subscribeSettingsWriteStatus` (`lib/settings/write-status.ts`) without rejecting, and `serializeSettings` drops `theme.backgroundImage` (stored separately via `saveBgImage` in `lib/theme-storage.ts`).

## Input and focus (TV / keyboard / gamepad)

- The focus engine is `lib/keyboard-navigation.ts` plus `keyboard-navigation/geometry.ts`, driven by `data-tv-*` attributes (`data-tv-nav-zone`, `data-tv-nav-cell`, `data-tv-initial-focus`, `data-tv-skip`, `data-tv-text-field`). Mark new layouts with these instead of custom key handlers.
- Activation keys are keyCodes 13/23/32 (Enter, remote Select, Space). Search-like fields take focus only and enter edit mode on activation (`isSearchLikeField`, `enterSearchEditMode`).
- The gamepad (`lib/gamepad/use-gamepad.ts`) feeds `dispatchTvNav`, so it inherits keyboard behaviour. Big Picture (`views/big-picture/`) has its own focus core (`bp-focus-core.ts`); the shell keyboard nav is disabled while it, the player or the picker is open.
- Hotkeys: defaults live in `HOTKEYS` (`lib/hotkeys.ts`) and user overrides in `settings.hotkeys`. Resolve through `effectiveBinding` / `findHotkeyMatch`, never hardcoded keys.
- Every app shortcut is a `HOTKEYS` row (Global, Player or Manga), never a raw `keydown` check on `e.key`: a hardcoded key can't be rebound and silently shares a key with the table. Only conventions stay fixed: Escape/Enter/Tab/arrows for navigation, media keys, and editor keys inside text tools (Ctrl+Z undo, Ctrl+P preview, comma in tag fields, Ctrl+W on the DJ deck window). Players outside the main view (PiP, video PiP, document PiP, trailers, music preview) reuse the player rows through `matchPlayerKey`; windows without `SettingsProvider` read overrides with `storedHotkeyOverrides`.
- `eventToBinding` keeps Shift on every key and lowercases letters, so Shift+K is `shift+k` and Caps Lock changes nothing. Number-key families are digit groups (`playerJumpDigits`, `globalRoomDigits`): the row stores only a modifier (`none`, `ctrl`, `off`), matched with `digitFromEvent`.
- Global rows stay live inside the player, so a new default must not collide with any Player or Global binding (`tests/hotkey-bindings.test.ts` checks every default pair). `effectiveBinding` drops a default whose key the user already gave to another action, so a new default never steals a key. An empty `defaultBinding` means unbound and Settings shows "Not set".

## Strings

- All UI text goes through `t()` / `useT()` from `@/lib/i18n`; see `lib/i18n/AGENTS.md`.
